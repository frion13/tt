# Playwright QA Skills для GigaCode

Скиллы помогают агенту прочитать тест-кейс из Jira или требования из Wiki, найти существующий автотест либо написать новый, выполнить проверку и сохранить Markdown-отчёт со скриншотами. При обнаружении дефекта агент оформляет отдельный Markdown-баг-репорт.

Ниже — установка в проект, который ты собираешься тестировать. Название его папки может быть любым. Команды подготовки можно выполнить самому или поручить агенту с доступом к терминалу.

## 1. Подготовь GigaCode и Node.js

Нужны установленный GigaCode (плагин в IDE или терминальный клиент), Node.js 22+ и npm. Проверь в терминале:

```bash
node --version
npm --version
```

Для установки пакетов Microsoft нужен доступ к настроенному npm registry. Наш код устанавливается с диска, публикация нашего пакета в npm не требуется.

## 2. Скопируй три скилла

В проекте, который будешь тестировать, создай `.gigacode/skills/` и скопируй туда папки **целиком**, включая вложенные файлы:

| Откуда взять в этом репозитории | Куда скопировать в своём проекте | Для чего |
| --- | --- | --- |
| `.gigacode/skills/playwright-mcp-cases/` | `.gigacode/skills/playwright-mcp-cases/` | Читать Jira/Wiki, составлять и проходить кейсы, исследовать продукт через MCP |
| `.gigacode/skills/playwright-cli-tests/` | `.gigacode/skills/playwright-cli-tests/` | Находить, создавать, обновлять и запускать автотесты |
| `.gigacode/skills/playwright-cli/` | `.gigacode/skills/playwright-cli/` | Официальные инструкции Microsoft для управления браузером через CLI |

Результат:

```text
твой-проект/
└── .gigacode/
    └── skills/
        ├── playwright-mcp-cases/
        ├── playwright-cli-tests/
        └── playwright-cli/
```

В каждом нашем QA-скилле есть инструкции и исполняемый код в `scripts/`. Официальный CLI-скилл содержит инструкции к отдельно устанавливаемой программе.

## 3. Установи зависимости и подготовь проект

Открой терминал **в папке своего проекта**, рядом с `.gigacode/`. Если `package.json` ещё нет, выполни:

```bash
npm init -y
```

После копирования всех трёх папок по шагу 2 выполни команды ниже как написано. Имена папок оставь исходными — ничего переименовывать или заменять в пути установки не нужно.

```bash
npm install --save-dev --install-links ./.gigacode/skills/playwright-cli-tests @playwright/test @playwright/cli
npx --no-install playwright-qa init
npx --no-install playwright install chromium
npx --no-install playwright-cli --help
```

Что делают команды:

| Команда | Результат |
| --- | --- |
| `npm install …` | Устанавливает общий код наших скиллов из локальной папки, а также Playwright Test и Playwright CLI из registry; записывает зависимости проекта |
| `playwright-qa init` | Создаёт отсутствующие конфигурации, `.env.example`, `AGENTS.md` и настройки CLI |
| `playwright install chromium` | Устанавливает Chromium для автотестов |
| `playwright-cli --help` | Проверяет, что программа CLI доступна |

`playwright-qa-skills` — имя нашего локального пакета с кодом обработки кейсов, запуска и отчётности. Его команда называется `playwright-qa`. Команда выше устанавливает общий код для обоих QA-скиллов. Отдельную npm-команду для `playwright-mcp-cases` выполнять не нужно; его папка остаётся на месте и используется агентом.

Параметр [`--install-links`](https://docs.npmjs.com/cli/v11/commands/npm-install/#install-links) устанавливает копию локального пакета в `node_modules`. Копировать `node_modules` из этого репозитория не нужно.

Если Playwright Test или CLI уже установлены, сохрани совместимые версии: убери соответствующие пакеты из команды `npm install`. `init` сохраняет существующие файлы. Если Playwright config уже был, добавь в него reporter `playwright-qa-skills/reporter` и `use.ignoreHTTPSErrors: true`, сохранив остальные настройки.

### Официальная установка CLI с нуля — справка

В шаге выше CLI уже установлен локально, а его официальный скилл скопирован в шаге 2. Повторная установка не нужна.

В [документации Microsoft](https://github.com/microsoft/playwright-cli#installation) приведён глобальный вариант:

```bash
npm install -g @playwright/cli@latest
playwright-cli --help
playwright-cli install --skills
```

Последняя команда устанавливает официальные инструкции. Если используешь этот способ вместо копирования из этой поставки, проверь выданный установщиком путь и перенеси полученную папку скилла целиком в `.gigacode/skills/playwright-cli/`. Не предполагается, что установщик автоматически выберет каталог GigaCode.

## 4. Подключи Playwright MCP к GigaCode

**Playwright CLI** — программа, которую агент вызывает командами терминала. **Playwright MCP** — сервер, через который GigaCode получает инструменты браузера. Для нашего полного процесса используются оба.

[Официальный способ подключения MCP от Microsoft](https://github.com/microsoft/playwright-mcp#installation) — запуск через `npx` из настроек клиента. Проверь доступность пакета:

```bash
npx -y @playwright/mcp@latest --help
```

Выбери настройки того GigaCode, которым пользуешься:

| Где работаешь | Куда добавить MCP |
| --- | --- |
| [GigaCode CLI в терминале](https://gitverse.ru/docs/ai/ai-assistant-gigacode/gigacode-cli/mcp) | `.gigacode/settings.json` проекта |
| [Плагин GigaCode в VS Code](https://gitverse.ru/docs/ai/ai-assistant-gigacode/gigacode-for-vscode/mcp) | Файл `gigacode.jsonc` в папке настроек расширения `.gigacode_vsc` |

Добавь конфигурацию:

```json
{
  "mcpServers": {
    "playwright": {
      "command": "npx",
      "args": ["-y", "@playwright/mcp@latest", "--ignore-https-errors"]
    }
  }
}
```

Если настройки уже существуют, добавь запись `playwright` в имеющийся `mcpServers`, сохранив другие настройки. Это официальный способ запуска с добавленным параметром `--ignore-https-errors`, который игнорирует ошибки сертификатов для всех страниц MCP-браузера.

`init` создаёт только пример `config/playwright-mcp.example.json`: он не подключает MCP к активному клиенту. После настройки перезапусти GigaCode. Сервер дальше запускает клиент — держать отдельный терминал с сервером не требуется.

## 5. Заполни .env и подключи правила агента

Если `.env` ещё нет, создай его по `.env.example`. Если уже есть — используй существующий файл. В нём должны быть URL, учётные данные и входные данные для нужных источников и стендов. Имена переменных могут отличаться от примера. Секреты не отправляй в Git и не вставляй в запрос агенту.

Поручи агенту:

```text
Прочитай AGENTS.md и подключённые QA-скиллы. Проверь профили для моего кейса.
Если нужных профилей нет, создай привязки по именам переменных .env
и контексту кейса: приложение — config/profiles.json,
Jira/Wiki — config/sources.json. Сохрани существующие настройки.
Значения секретов не выводи. Неоднозначные соответствия уточни.
```

В профилях хранятся имена env-переменных. Учётные данные Jira/Wiki отделены от учётных данных приложения. `init` создаёт пустой файл профилей приложения; соответствия определяет агент по правилам скиллов.

`AGENTS.md` создаётся в корне проекта командой `init`. Если там уже свои инструкции, они сохраняются, а QA-правила записываются в `PLAYWRIGHT_QA.md`. Включи их в активные инструкции GigaCode; если клиент не читает эти файлы автоматически, явно попроси агента прочитать их. После копирования скиллов обнови сессию агента и проверь, что он их видит.

## 6. Проверь браузер

В терминале проекта проверь CLI:

```bash
npx --no-install playwright-cli open https://example.com
npx --no-install playwright-cli snapshot
npx --no-install playwright-cli close
```

В чате GigaCode проверь MCP:

```text
Через Playwright MCP открой https://example.com, прочитай страницу
и сохрани скриншот в reports/mcp-check.png.
```

В терминальном GigaCode состояние подключения можно посмотреть через `/mcp`. Проверка считается успешной после фактического открытия страницы и сохранения скриншота.

Если CLI или MCP сообщает об отсутствии браузера, установи браузер по сообщению соответствующего инструмента: Chromium для автотестов не гарантирует наличие браузера, выбранного CLI/MCP. Если GigaCode не находит `npx`, проверь PATH процесса IDE и перезапусти её после установки Node.js.

## 7. Отправь задачу агенту

Для кейса из Jira:

```text
Выполни кейс <ссылка на Jira>. Найди существующее покрытие.
Если актуальный автотест есть — запусти; если нет — создай
или обнови и запусти. Сохрани Markdown-отчёт со скриншотами.
При обнаружении дефекта сохрани отдельный Markdown-баг-репорт.
```

Для документации:

```text
По документации <ссылка на Wiki> составь тест-кейсы,
автоматизируй и выполни их. Неясные требования уточни.
Сохрани отчёты со скриншотами и баг-репорты при дефектах.
```

Для исследования:

```text
Проведи исследовательское тестирование <продукт/функция> на <стенд>.
Сохрани журнал со скриншотами, найденные баги и новые тест-кейсы.
```

После чтения Jira/Wiki агент открывает отдельную вкладку или CLI-сессию тестового стенда по URL из `.env` и проверяет адрес и интерфейс приложения. Только затем выполняет шаги. Если стенд не определён, прогон блокируется; действия на портале с описанием кейса не заменяют тестирование приложения.

Агент сам выбирает скиллы и выполняет команды поиска, регистрации и запуска. Скиллы взаимодействуют через файлы проекта: кейсы, профили, реестр и spec-файлы. Написание тестов выполняет агент, а сохранённый код запускает Playwright Test.

**Сейчас отправляй ссылку вместе с действием**, как в примерах. Одна ссылка без пояснения по текущим правилам может вызвать уточнение, а не полный прогон.

## Где искать результат

| Файлы проекта | Содержимое |
| --- | --- |
| `test-cases/` | Markdown-кейсы с шагами, ожиданиями, источником и профилем |
| `e2e/` | Созданные автотесты; в существующем проекте агент учитывает принятую структуру |
| `config/registry.json` | Связи кейсов с автотестами и ревизиями |
| `reports/` | Markdown-отчёты, папки скриншотов и баг-репорты |

После каждого выполненного UI-шага сохраняется скриншот либо причина его отсутствия. Передавай Markdown-отчёт вместе с папкой изображений. Падение создаёт черновик бага, а агент определяет причину; автоматической публикации в Jira нет.

Ошибки сертификатов игнорируются в тестовых контекстах runtime, в CLI через созданный `.playwright/cli.config.json` и в MCP через указанный флаг. Это не авторизует вход на сайт: для него нужны отдельные данные из `.env`.

Форматы и команды входят в каждый QA-скилл: `references/runtime.md` и `references/runtime-api.md`. В этом репозитории также доступны [описание runtime](.gigacode/skills/playwright-cli-tests/references/runtime-api.md) и [происхождение официального скилла](third-party/README.md).
