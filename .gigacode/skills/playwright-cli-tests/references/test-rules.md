# Правила поддерживаемых автотестов

## Структура и проверки

- Следуй соглашениям проекта. Тест выражает один самостоятельный сценарий; Arrange/Act/Assert разделяй логически. Для длинного сценария используй `test.step` с осмысленным названием, не дроби зависимые шаги на зависимые тесты.
- Название содержит ID кейса и проверяемый результат. Каждое обязательное ожидание имеет assertion: видимость нужного состояния, точное значение/количество, URL или результат операции. Проверяй отрицательные сценарии на конкретную ошибку и отсутствие запрещённого эффекта, когда это предусмотрено кейсом.
- Используй `await expect(locator).to...` для UI-состояний; не заменяй повторяемую проверку `expect(await locator.isVisible()).toBe(true)`.
- Предпочитай `getByRole` с accessible name, `getByLabel`, затем стабильные test IDs по соглашению проекта. Уточняй область поиска. CSS/XPath и `nth/first` допустимы только при обоснованной семантике; не маскируй неоднозначный локатор первым совпадением.
- Не используй фиксированные sleep/`waitForTimeout`, безусловный `force: true` и `networkidle` как универсальную готовность. Жди конкретный элемент/состояние или нужный ответ. При ожидании события зарегистрируй ожидание до действия, которое его вызывает.
- Codegen/CLI-фрагмент — заготовка: отредактируй локаторы, добавь предусловия, assertions и cleanup перед включением в набор.

## Изоляция и данные

- Отдельный browser context на тест через стандартные fixtures; не делись изменяемым `page` между тестами. Общий неизменяемый auth state возможен, общий изменяемый аккаунт должен учитывать параллельность.
- Создавай уникальные сущности через фабрики/fixtures; фиксируй время/случайность, когда они влияют на ожидание. Cleanup выполняй через teardown/`finally` только для собственных данных, без удаления чужих записей.
- Все входные тестовые данные, секреты, base URL и путь к auth state получай из env через единый модуль валидации по [контракту](case-contract.md). Fixtures потребляют проверенные значения, а не содержат их копии. Негативные/граничные входы также задавай через env; отсутствие переменной и намеренно пустое значение различай. Не коммить `.env`, cookies и storage state. Не выводи секреты в отчёты.
- Setup через API допустим, если он не заменяет проверяемое UI-действие. Моки вводи для согласованной изоляции внешних зависимостей; не мокай основной проверяемый backend ради успеха E2E.
- Выноси повторяющиеся UI-операции в Page/Component Objects, подготовку данных в fixtures, когда это уменьшает дублирование. Не создавай иерархии абстракций для каждого одиночного клика. Бизнес-ожидания должны оставаться читаемыми в тесте или явно названных assertion helpers.

## Диагностика и CI

- Переиспользуй конфигурацию проекта. Для нового набора задай testDir, baseURL из окружения, изоляцию и артефакты падения (например trace `retain-on-failure`, screenshot `only-on-failure`). Дополнительно собирай скриншоты каждого выполненного UI-шага для обязательного Markdown-отчёта: настройка `only-on-failure` этого не обеспечивает. Отсутствующий обязательный URL должен давать понятную ошибку.
- Сохраняй trace и отчёты с учётом наличия в них чувствительных данных. Используй HTML/JUnit/JSON reporter, который нужен проекту; не перезаписывай существующий список без причины.
- Не оставляй `test.only`, немотивированные skip/fixme, пустые assertions, проглоченные ошибки и автообновление snapshots. В CI включай запрет `only`, если настраиваешь новый runner.
- При повторе учитывай результаты всех попыток. Проверяй изменённый тест и связанное покрытие, не скрывай flaky тест увеличением retries. Для нового теста разумно проверить повторяемость, если сценарий зависит от асинхронности или параллельных данных.

Официальные справочники: [практики](https://playwright.dev/docs/best-practices), [assertions](https://playwright.dev/docs/test-assertions), [fixtures](https://playwright.dev/docs/test-fixtures), [изоляция](https://playwright.dev/docs/browser-contexts), [trace](https://playwright.dev/docs/trace-viewer), [CLI runner](https://playwright.dev/docs/test-cli). При несовпадении API сверяй установленную версию.
