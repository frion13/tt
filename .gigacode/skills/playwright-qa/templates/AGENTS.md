# Правила тестирования проекта

Для задач тестирования используй `playwright-qa` из `.gigacode/skills/playwright-qa/SKILL.md`. Для остальных задач не подключай его автоматически. Корень проекта определяй по текущему workspace.

Скилл содержит весь процесс: MCP-чтение источника, составление кейсов, исследование, автоматизацию, env-профили и отчётность. Читай только нужные references по ссылкам из SKILL.md. Официальный `playwright-cli` подключай для управления браузером через CLI.

## Маршрутизация

| Запрос | Раздел скилла |
| --- | --- |
| Прочитать источник кейса или документации, составить кейсы | references/mcp-cases.md |
| Автоматизировать или выполнить кейс с созданием автотеста | Полный цикл в SKILL.md → references/automation.md |
| Явный ручной прогон без автотеста | references/mcp-cases.md |
| Исследовательское тестирование | references/exploratory.md |
| Разобрать падение, оформить баг | references/automation.md и references/runtime-api.md |

Одна ссылка без действия: используй контекст запроса; если намерение неизвестно, прочитай доступный источник и уточни режим перед выполнением сценария. Явные ограничения пользователя имеют приоритет.

## Обязательные условия

- Создавай отсутствующие профили по именам переменных `.env` и контексту по контракту скилла. Рабочие файлы: `config/profiles.json` для приложения, `config/sources.json` для источников. Сохраняй существующие профили, не раскрывай секреты и уточняй неоднозначности.
- После чтения источника перейди на стенд из профиля приложения в отдельной вкладке/сессии. Проверь фактический URL и продукт новым snapshot до первого действия. Портал кейсов не заменяет приложение; неизвестный стенд — blocked.
- Задача автоматизации требует проверки покрытия, создания/обновления spec при необходимости и запуска runner. MCP-прогон или ответ MCP-субагента — промежуточный результат. Продолжи работу основным агентом либо сообщи конкретный блокер.
- Для завершённой автоматизации укажи путь к spec, результат runner и отчёт. Для ручного прогона или исследования достаточно соответствующего журнала. Не приписывай непроверенным шагам passed.
- Сохраняй Markdown и скриншоты после прогона, отдельные Markdown-баги при дефектах. Различай продуктовые дефекты и ошибки теста/окружения. Автоматической публикации во внешней системе нет.
- Общий runtime устанавливается локально из папки `playwright-qa`, команда — `playwright-qa`, импорты — `playwright-qa-skills/test` и `playwright-qa-skills/reporter`. Установку смотри в references/runtime.md. Наличие скилла не означает подключённый MCP или CLI.
